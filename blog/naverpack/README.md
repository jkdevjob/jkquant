# 네이버 업로더용 매일 패키지 (클로드 몫)

> 2026-11-04부터 드라이브 패키지는 만들지 않는다. 사용자가 "지피티가 만든 자동 업로드 프로그램이 잘 안 돌아가네",
> "블로그 그냥 작성하고 매일 아침에 알림을 줘라 그때 일회용 비밀번호로 올리자"라고 했다. 원고 규칙·도표·검사 도구는
> 그대로 쓰고, 게시는 `../naver/README.md` '매일 흐름'대로 일회용 번호로 직접 한다.

사용자 PC의 '매니악 블로그 업로더'가 구글 드라이브 폴더 **ManiacNaverInbox**
(`1z-fxebjUshk_dMZwGPdl02Dir8Gch2h7`)의 `.naverpack.zip` 을 읽어 네이버 블로그(maniacjk)에 올린다.
GPT가 매일 새벽 5시께 `YYYYMMDD_hotissue.naverpack.zip` 하나를, 클로드가 매일
`YYYYMMDD_hotissue-claude.naverpack.zip` 하나를 넣는다(사용자 지시 2026-11-02: "지피티도 하나 너도 매일 하나").

드라이브에 넣는 것까지가 이 작업이다. 네이버 게시는 업로더가 하고, PC가 잠자기면 깨어날 때 올라간다.
네이버 글 목록에서 직접 확인하기 전에는 '네이버 발행 완료'라고 쓰지 않는다.

## 규칙

- 같은 폴더에 이미 오늘 날짜 `_hotissue-claude` 패키지가 있으면 새로 만들지 않고 그 링크만 알린다.
- 밀린 날짜 몫을 나중에 만들 때는 파일 이름·`date` 를 그 날짜로 두고 `verify_pack.py --date YYYYMMDD` 로 검사한다.
- 내가 올리지 않은 파일(GPT 패키지 등)은 지우거나 덮어쓰지 않는다.
- 주제: blog/GUIDE.md '주제 고르기'를 따르되, **같은 날 GPT 패키지 주제와 지난 7일 네이버 글 주제는 피한다.**
  먼저 네이버 글 목록을 본다:
  `https://blog.naver.com/PostTitleListAsync.naver?blogId=maniacjk&currentPage=1&categoryNo=0&countPerPage=30`
  GPT의 오늘 글이 아직 목록에 없을 때만 GPT 패키지를 `download_file_content` 로 받아 `peek_pack.py` 로 제목을 본다
  (180KB 안팎이라 결과가 tool-results 파일로 저장되며, 스크립트가 그 파일도 찾는다).
- 숫자·인용은 서로 다른 출처 3곳 이상의 원문에서 확인한다. 확인 못 한 숫자·인용은 넣지 않는다.
  보도마다 다르면 범위로 쓰거나 '보도마다 차이'를 밝힌다.
- 종목 매매 추천, Anthropic 관련 이슈는 다루지 않는다.

## post.json

```json
{"schema_version": 1, "id": "YYYYMMDD-hotissue-claude-<영문>", "date": "YYYY-MM-DD",
 "blog_id": "maniacjk", "title": "18~40자", "topic": "비즈니스·경제",
 "tags": ["5~8개", "#·공백·쉼표 없이"],
 "blocks": [
  {"type": "paragraph", "text": "도입 한 줄(번호 없음, 160자 안)"},
  {"type": "image", "file": "images/00.png", "caption": "썸네일", "thumb": true},
  {"type": "paragraph", "text": "1. 한 줄에 사실 하나, '~임/~함/~음/~됨'으로 끝맺음."},
  {"type": "paragraph", "text": "2. …"},
  {"type": "image", "file": "images/01.png", "caption": "도표 설명 한 줄(단위·기준 시점)",
   "links": [{"label": "언론사 기사제목", "url": "https://…"}]},
  {"type": "paragraph", "text": "※ 정보 제공 목적의 글이며 투자 권유가 아님."},
  {"type": "paragraph", "text": "한줄 코멘트. 그래서 어떻게 보나, 판단 한마디(60~220자, 3문장 이하) — 글의 맨 끝."}
 ]}
```

**글 형식 = 메르 형식(2026-11-20~, 사용자 "메르 분석해서 하는 그대로 내일 제작해 내용 길게 이미지도 좀 더 넣고").**
메르 최근 12개 글을 잰 값(STRATEGY_LAB 2026-11-19 (4)): 번호 줄 중앙값 48(상위 25% 67) · 한 줄 평균 51자 · 끝맺음 '~임/~함/~음/~됨'
· 글자 수 중앙값 2,945(상위 25% 3,881) · 이미지 중앙값 8(상위 25% 11) · 글과 이미지가 번갈아 · 끝에 '한줄 코멘트' · 뉴스 주소 0 · 제목 중앙값 26자.
**메르의 문장·글·이미지는 옮기지 않는다 — 모양만 따른다.** 메르의 도입 문구도 그대로 쓰지 않고 우리 말로 쓴다.
`verify_pack.py` 가 아래를 전부 검사한다.

- 맨 앞: 번호 없는 도입 한 줄(160자 안. 예: '숫자는 발표와 기사에서 확인했고, ○○ 부분은 개인적인 생각이 섞여 있음.') → 바로 썸네일.
- 본문: **번호 줄 55~90개**, 1부터 빠짐없이. **한 문단 = 번호 줄 하나 = 사실·생각 하나**(줄 안에 줄바꿈 없음, 평균 30~90자, 한 줄 180자 이하).
  끝맺음은 '~임·~함·~음·~됨'(70% 이상) — `blog/2026-11-19_fed-bigstep.md` 의 줄 모양과 같다(그 글과 내용은 달라야 한다).
- 흐름: 무슨 일이 있었나(사실) → 숫자로 보면 → 왜 그런가(배경·원인) → 누가 이득·손해인가 → 우리 증시·내 돈에는(계산 예시 1개 이상) →
  반대 시나리오·남은 변수 → 앞으로 볼 일정·지표. 소제목 대신 '그럼 ○○은 어떨까.' 같은 번호 줄로 넘어간다(메르는 인용구·소제목을 안 쓴다).
  **AI 느낌 덜 나게(2026-11-20 사용자 "AI 느낌 덜나게 못할까?" · 메르 10개 비교, `verify_pack` 이 검사):**
  - (해석)·(계산) 꼬리표 금지 — 해석은 말투로 드러낸다: '~같음·~보임·~라고 봄·개인적으로는 ~'. 자기 목소리 줄 3개 이상.
  - '~라고 보도됐음' 2번까지. 3곳 이상 확인한 사실은 그냥 사실로 쓰고, 한 곳만 말한 것은 '○○일보 기사를 보면'처럼 언론사 이름으로.
  - 첫째·둘째·셋째 나열 금지(옵션·종류는 '옵션 1은 ~임'처럼 문장으로). '그럼 ~'·'이제 ~'로 시작하는 이음말 줄 2개까지.
  - '~하는 셈임'·'다만'·'가능성이 큼'·'비유하면' 같은 버릇 말을 반복하지 않는다. 짧은 줄과 긴 줄을 섞는다.
  - 경험은 지어내지 않는다 — '내가 가입했는데' 같은 겪은 일은 사용자 '내 생각' 칸에서만. 우리는 판단·생각만 쓴다.
  - 면책은 '※' 한 줄만(번호 줄로 또 쓰지 않음). 비유는 1~2개, '비유하면'이라는 말 없이.
- 본문(문단 글자 합) **3,500~5,500자**. 번호 줄 뒤에 '※' 한 줄, 그리고 **글의 맨 끝은 '한줄 코멘트.'로 시작하는 문단**(2026-11-20 사용자 "글 맨끝에 한줄코멘트로 정리한 글 있던데 우리도 한줄정리 넣자").
  메르 12개 중 10개가 한줄 코멘트로 끝남 — 맨 마지막 줄 · 중앙값 약 150자 · 1~3문장 · 숫자 나열보다 '그래서 어떻게 보나' 판단 한마디(해석이므로 본문이 증명하는 범위 안에서).
  우리 기준: 60~220자 · 3문장 이하 · 맨 끝(`from_pack` 이 '자료:' 줄을 그 앞에 넣고, `phone_pack` 은 사용자 '내 생각' 칸을 그 앞에 둔다). 번호 없는 문단은 4개까지.
- 문단에 링크·HTML·마크다운 없음. `links` 의 주소는 **사실 확인 기록용**이다 — 네이버 글에는 주소를 넣지 않고
  `from_pack.py` 가 글 맨 끝에 `자료: 언론사 · 언론사` 한 줄만 만든다(2026-11-19 사용자 "출처 주소 줄 빼고 해").
  label 은 '언론사 기사제목' 순서로 쓰거나 `"src": "언론사"` 를 따로 준다.
- 이미지 **8~12개**: **첫 이미지는 썸네일**(`thumb.js`, 정사각형, `"thumb": true`, 도입 줄 바로 뒤) + 직접 만든 그림 7~11개를
  번호 줄 5~10개마다 하나씩(이미지끼리 붙이지 않음 · 이미지 없이 번호 줄 16개 넘게 잇지 않음). 쓸 수 있는 도구:
  `chart.js`(막대) · `timeline.js`(일정·흐름) · `table.js`(비교·조건·계산 정리표) · `card.js`(핵심 숫자 카드 — 큰 숫자 하나 + 설명).
  같은 도구만 몰아 쓰지 말고 섞는다. 그림마다 본문과 직접 관련 있어야 하고(공식 가이드: 무관한 이미지 나열 금지),
  그림 속 핵심 숫자는 본문 글자로도 쓴다(`--nums` 로 확인). 사진(인물·뉴스 사진)은 쓰지 않는다(초상권·저작권).
  사진 설명(caption)은 한 줄, '도표:' 머리말 없이. 썸네일 설명은 네이버 글에 넣지 않는다.
- 제목 18~40자: 검색어를 앞 10자 안에 + 메르처럼 짧은 질문·'~의 비밀'·'(feat 검색어)' 꼴. GUIDE '제목 짓기' 6개 기준.
- `post.json` 의 `category` 는 블로그 카테고리(GUIDE 1장 표: 경제·IT·과학·사회·정치·국제·연예·방송·스포츠·생활·건강)다.
- `post.json` 의 `topic` 은 네이버 주제 이름이다(이슈에 맞게: 스타·연예인, 방송, 드라마, 영화, 스포츠, 사회·정치, 건강·의학,
  IT·컴퓨터, 비즈니스·경제, 교육·학문, 자동차, 게임, 국내여행, 세계여행, 맛집, 요리·레시피, 일상·생각 등). 틀리면 발행이 멈춘다.
- 금지 키: `category_no`, `demo_only`, `already_published_url`.

## 순서

작업 폴더 W 를 하나 만들고(스크래치 폴더 아래), 도구는 이 폴더에서 받아 쓴다.

```
node chart.js W/charts.json W/images          # 도표(가로 막대, 음수면 양방향)
node timeline.js W/timeline.json W/images     # 일정·흐름표
node table.js W/tables.json W/images          # 정리표(비교·조건·계산)
node card.js W/cards.json W/images            # 핵심 숫자 카드
python3 -I build_pack.py W W/out/YYYYMMDD_hotissue-claude.naverpack.zip   # 6색 PNG + ZIP + .b64
python3 -I verify_pack.py W/out/…zip --nums '도표숫자1|도표숫자2|…'          # RESULT: PASS 여야 함
fold -w 2000 W/out/…zip.b64 > W/out/b64_folded.txt
```

1. 드라이브 `create_file`: title 최종 이름(`.partial` 쓰지 않음 — 업로더가 중간 이름을 보고 건너뛴 적이 있다),
   parentId 위 폴더, contentMimeType `application/zip`, disableConversionToGoogleType true,
   base64Content 는 b64_folded.txt 줄을 줄바꿈 없이 이어 붙인 값.
2. 결과 fileSize 가 ZIP 크기와 같은지 본다.
3. `download_file_content(fileId)` → `python3 -I check_upload.py <fileId> <zip>` 가 `MATCH` 여야 '드라이브 전달 완료'.
   MISMATCH 면 내가 방금 올린 그 파일만 휴지통으로 보내고 한 번 다시 올린다.
4. 보고(한국어): 제목·기준 날짜 / 문단·이미지·태그 수 / ZIP 이름 / 검증 결과 / 드라이브 링크 / 주요 출처.

지난 원고는 `posts/` 에 날짜별로 남긴다(새 세션 예약은 저장소에 푸시하지 못하므로 그날 원고는 드라이브 ZIP 이 원본이다).
