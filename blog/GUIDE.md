# 일일 경제 핫이슈 블로그 작성 규칙

매일 아침 한 편. 예약 작업이 이 문서를 읽고 그대로 따른다.
기준 예시: `2026-10-26_oil-rate.md`

## 1. 주제 고르기

**주제 기준(사용자 지시 2026-11-09, 이전 규칙보다 우선):**
"모든 카테고리 주제를 다루지만 경제 비즈니스 외에는 정말 핫이슈라 누구나 궁금한것만 올려.
하루에 최대 3개지 핫이슈가 없으면 굳이 3개 안써도 돼."
(그 전 지시 2026-11-08: "주제를 경제 비즈니스에 한정하지 말고 무조건 어제 핫했던걸 기준으로 주제 선정해. 사람들이 궁금해 할만한거.
제목이나 썸네일도 호기심을 불러오게 최대한 고민해서 만들어." — 제목·썸네일 부분은 그대로 유효)
- **경제·비즈니스**(증시·금리·환율·부동산·세금·연금·물가·기업 실적, 반도체·AI·자동차 같은 산업의 사업·투자 이야기)는 평소 기준으로 쓴다:
  `python3 -I blog/hot_topics.py` 의 '많이 본 뉴스'·'댓글 많은 뉴스' 이슈 묶음에서 언론사 수가 많은 순.
- **그 밖의 분야**(연예·스포츠·사회·정치·국제·생활·건강, 돈 얘기가 아닌 IT·과학)는 **'정말 핫이슈'일 때만** 쓴다. 셋 다 만족해야 한다.
  1. 판이 크다: '많이 본 뉴스' 묶음 언론사 **12곳 이상**, 또는 구글 트렌드 **5,000+ 이상**(`hot_topics.py` 출력의 ★ 표시).
     '댓글 많은 뉴스'에서만 많은 이슈(정치 공방·말싸움 등)는 '누구나 궁금한 것'으로 보지 않는다.
  2. 사람들이 실제로 찾아본다: `python3 -I blog/keywords.py <이슈 낱말>` 자동완성에 그 이슈 검색어(이유·뜻·나이·할인·일정 등)가 뜬다.
  3. 아래 분야별 선을 지킬 수 있다.
- 1번 글은 위 기준을 통과한 이슈 가운데 가장 뜨거운 것이다. 경제가 아닌 이슈가 하나도 통과하지 못하면 경제·비즈니스에서 고른다.
  매일 1개는 쓴다. 지난 7일 글과 겹치면 큰 진전일 때만, 아니면 다음 이슈.
- 예(2026-11-09 아침 `hot_topics.py`): 삼성 12년 만의 KS 우승은 많이 본 13곳 + 자동완성 '삼성 우승 할인'·'삼성 우승 혜택'이라 통과.
  '한동훈 복당론'은 많이 본 9곳·댓글 17곳이라 통과하지 못한다(댓글만 많은 정치 공방).
- 글의 뼈대는 "사람들이 그 뉴스를 보고 바로 검색할 질문"에 답하는 것이다: 무슨 일? 왜? 확인된 것과 아닌 것? 나와 무슨 상관?
  다음에 볼 것? 검색어는 `python3 -I blog/keywords.py <이슈 낱말>` 의 자동완성에서 고른다(예: '젠슨 황 딸', '사이버트럭 단종 이유').
- 이슈 검색은 하루 이틀 안에 몰린다. 그래서 아침 일찍 올리는 것이 유입의 절반이다(노트북 자동 게시가 중요한 이유).
- **참고 블로그 — 메르의 블로그(blog.naver.com/ranto28)** (사용자 지시 2026-11-13 "이 블로그 참고해 여기가 주제선정을 잘하네").
  2026-10-04~11-13 글 90개를 본 결과(`STRATEGY_LAB.md` 5장). 방식만 배우고 문장·표현·꼭지 이름은 베끼지 않는다.
  1. **뉴스가 아니라 '투자자가 묻는 질문 하나'가 주제다.** 같은 젠슨 황 사건도 불륜 자체보다 "젠슨 황이 없어도 엔비디아가 돌아갈까?",
     "공매도 리포트는 이미 알고 있었다"처럼 돈·회사 구조 쪽 질문을 잡는다. 주제를 고르면 그 이슈로 가장 궁금할 질문 하나를 먼저 적고,
     글 전체가 그 질문에 숫자로 답하게 쓴다(번호 문단을 질문 → 근거 → 답 순서로).
  2. **한 분야를 깊게.** 90개 중 62개가 한 카테고리(경제·투자)다. AI 인프라(엔비디아·구글 TPU·앤트로픽·코어위브·데이터센터 전기),
     반도체(삼성·SK하이닉스), 미국 금리·국채, 국장 수급, 선거·전쟁 같은 지정학을 모두 '돈'으로 연결한다. 경제 밖 핫이슈를 쓸 때도
     가능하면 돈·산업과 이어지는 질문으로 쓴다.
  3. **1차 자료를 뜯어본다.** 실적 발표·상장 신고서·국채 입찰 결과·CPI·예산안처럼 원문을 읽고 핵심 숫자를 풀어 준다(기사 요약이 아님).
  4. **이어 쓰기.** 같은 이야기가 진행되면 후속 글로 이어 쓰고 앞 글을 본문 끝 '지난 글'로 소개한다(90개 중 10개가 후속편).
  5. **장 시작 전 '오늘 우리 증시'.** 간밤 미국 이슈가 오늘 코스피·삼성·SK하이닉스에 무슨 뜻인지 — 우리 1번 글(05시대 발행)과 맞는 자리다.
  6. 제목: 90개 중 45개가 물음표, 24개가 '(feat 핵심어)'. '~의 비밀', '~뜯어보기', '~사실일까/맞나?(팩트체크)'. 평균 27자.
  주의: 그 블로그는 구독자가 많아 글마다 공감이 수백~수천이다. 우리는 아직 검색이 거의 유일한 통로라 노린 검색어(keyword)는 계속 넣는다.
- 분야별 선 — 지키지 않으면 쓰지 않는다:
  - 사건·사고([주의] 표시): 피해자·가해자 신상, 잔혹한 묘사, 추측한 동기를 쓰지 않는다. 확인된 경위와 제도·안전 정보 중심.
  - 연예·사생활·의혹: 보도로 확인된 사실과 당사자 공식 입장만. 루머·추측·사생활 캐기 금지. 의혹은 "~라고 보도됐다"로만.
  - 간첩·안보 의혹(사용자 지시 2026-11-10 "중국 스파이에 관련해서 써도 괜찮을거 같은데"): 공익이 큰 안보 의혹은 글의 중심 주제로 써도 된다.
    제목·썸네일에 '중국 스파이 의혹'처럼 쓰되 반드시 '의혹'·'의심'을 붙인다(스파이라고 단정 금지). 주요 언론이 실명으로 보도한 인물은
    이름과 회사·직책, 의혹 내용, 당국·당사자·중국 정부의 입장까지 쓴다. 누가 무엇을 의심하는지(예: 미 정보당국, 익명 소식통)를 밝히고,
    확인된 것과 아닌 것을 나눈다. 연애·신체 접촉 사진 묘사, 가족·주소 같은 사생활은 쓰지 않는다.
  - 정치: 양쪽 주장을 같은 무게로 옮기고 쟁점·절차를 정리한다. 편들지 않는다. 비난·조롱 표현 금지.
  - 건강·의학: 공식 기관·학회 근거가 없으면 쓰지 않는다.
  - 모든 분야: 숫자·인용은 서로 다른 출처 3곳 이상. 종목 매매 추천·Anthropic 관련 이슈는 다루지 않는다.
- 네이버 `topic` 은 이슈에 맞는 네이버 주제로 바꾼다.
- **블로거 '은퇴노트'(retire-note.blogspot.com)** — 2026-11-13 사용자가 블로그·프로젝트를 retire-note 로 만들어 키를 등록했다
  ("앞으로는 자동으로 올릴수 있게 구글 블로거에 올리자"). 클로드만 하루 1개, GitHub Actions 로 자동 게시(5장). GPT 는 쓰지 않는다.
  - 독자: 은퇴를 앞두었거나 은퇴한 50~60대. 주제: 노후 돈 관리(국민연금·퇴직연금·IRP·연금저축·ISA·건강보험료·주택연금·금융소득과세)와
    그날 경제 이슈를 '내 노후 돈' 관점으로 본 글. 한 분야를 깊게(참고 블로그 원칙 2).
  - 고르는 순서: ① 그날 네이버 1번 이슈가 노후 돈(금리·연금·세금·증시·환율·부동산)과 이어지면 그 관점의 질문 하나로 쓴다
    (예: 젠슨 황 사임 → "내 연금·ETF 속 엔비디아는 얼마나 되나?"). ② 이어지지 않으면 `topics_evergreen.md` 에서 아직 안 쓴 상록 주제를
    위에서부터 쓰고 그 표의 '쓴 날짜'를 채운다. 제도 숫자(감액률·한도·세율)는 공식 기관 원문으로 확인하고 기준 연도를 밝힌다.
  - 제목은 자동완성 검색어를 앞에 둔 질문형(구글에서도 같은 질문으로 찾는다). 네이버 글과 제목·문장은 따로 쓴다(중복 콘텐츠 금지).
  - **공개 시각: 매일 05:00(한국)** (사용자 지시 2026-11-13 "매일 아침 5시에 은퇴노트에 자동으로 올리고 네이버는 5시 10분에 로그인 알림줘 기존대로").
    글 3행에 `<!-- publish_at: <오늘 날짜>T05:00:00+09:00 -->` 를 쓴다. 03:17 에 써서 푸시하면 블로거에 예약되고 05:00 에 공개된다
    (05:00 이 지난 뒤에 푸시하면 바로 공개). 05:10 루틴이 공개 주소를 열어 확인한다.
  - 컨셉에 맞지 않게 올라간 글은 `blog/blogger_revert.txt` 에 적어 푸시하면 '초안'으로 내려간다(지우지 않음).
- **블로거 '매니악 브리핑'(maniacbriefing.blogspot.com)** — 2026-11-13 사용자가 만듦. GPT 'GPT 만들기'가 계정에서 막혀 있어(읽기 전용)
  클로드가 하루 1개를 자동 게시한다. 글 3행 `<!-- blog: maniac -->`, 4행 `<!-- publish_at: <오늘>T07:00:00+09:00 -->`(장 시작 전).
  - 주제: 경제·투자 핫이슈를 '참고 블로그' 원칙(투자자 질문 하나 · 1차 자료 숫자 · 간밤 미국과 오늘 우리 증시)으로. 이미지 2개(썸네일 brand '매니악 브리핑').
- **중복 방지(사용자 2026-11-13 "네이버와 블로거 글이 중복되면 페널티 받을텐데 어쩌지") — 모든 블로거 글:**
  1. 같은 날 네이버 글과 **같은 이슈를 쓰지 않는다.** 은퇴노트는 노후 돈·상록 주제, 매니악 블로거는 네이버 1·2번이 다루지 않은 이슈
     (예: 네이버가 '엔비디아 주가 하락 원인'이면 블로거는 '그날 코스피·삼성·SK하이닉스는 왜 올랐나'). 큰 사건 하나뿐이라 겹칠 수밖에 없으면
     질문·구성·제목·표를 모두 다르게 하고 2번 검사로 확인한다.
  2. `python3 -I blog/dup_check.py <파일>` 이 RESULT: PASS(네이버·다른 블로거 글과 7글자 묶음 겹침 15% 이하)일 때만 푸시한다.
     기준 잡기(11/13): 따로 쓴 국민연금 글 0.6%, '문장만 새로 쓴' 젠슨 황 블로거 글 26.7%(FAIL — 같은 이슈를 같은 순서로 쓰면 이렇게 겹친다).
  3. 네이버 이미지를 블로거에 다시 쓰지 않는다(그림도 새로 만든다).
  4. 네이버 글을 먼저 올린다(05시대). 블로거는 은퇴노트 05:00(다른 주제), 매니악 07:00.

**하루 글 수(사용자 지시 2026-11-08 "핫이슈나 조회수가 나올만한 주제가 혹여나 하나가 아니라 여러개라면 하루에 최대 3개까지 올려",
2026-11-09 "하루에 최대 3개지 핫이슈가 없으면 굳이 3개 안써도 돼"):**
- 1개가 기본, **최대 3개.** 3개를 채우려고 쓰지 않는다. 2·3번째 글은 아래를 모두 만족할 때만 쓴다. 약한 주제로 숫자를 채우지 않는다.
  1. 1번과 다른 이슈다(같은 사건의 다른 면이 아니다).
  2. 신호가 강하다: 경제·비즈니스는 '많이 본 뉴스' 묶음 언론사 8곳 이상, 또는 '댓글 많은 뉴스' 묶음 5곳 이상, 또는 구글 트렌드 1000+ 이상.
     그 밖의 분야는 위 '정말 핫이슈' 기준(많이 본 12곳+ 또는 트렌드 5,000+, 그리고 자동완성 검색어).
  3. 지난 7일 글과 겹치지 않는다.
  4. 분야별 선을 지킬 수 있고, 출처 3곳 확인·썸네일·도표까지 1번과 같은 품질로 쓸 수 있다.
- 되도록 서로 다른 카테고리로 고른다(예: IT·과학 + 사회 + 생활·건강). 같은 카테고리 3개는 피한다.
- `post.json` 에 `priority`(1·2·3)를 적는다. 게시는 1번부터 차례로 한다.
- 블로거 '은퇴노트'는 네이버 글 수와 별개로 하루 1개(위 '블로거 은퇴노트' 기준).
- **실험 E1(2026-11-12 사용자 승인 "어", `STRATEGY_LAB.md`):** 11/06 부터 새 글이 검색에 안 잡혀서 몰아 올리기를 끊는다.
  클로드 글은 **하루 최대 2개** — 1번은 로그인 직후 바로, 2번은 **12:00 예약 발행**(1번과 3시간 이상 간격). 3번 글은 쓰지 않는다.
  GPT 글은 2026-11-13 부터 없다(사용자 "지피티는 하지 말라고 했어" — 네이버는 클로드 글만). 원고 json 에 `keyword`(노린 자동완성 질문형 검색어)를 적는다.
  예약 시각을 화면에서 다시 읽어 맞을 때만 예약하고, 맞지 않으면 2번 글은 올리지 않는다.

| 해외 정치·전쟁·외교 | 국제 | 사회·정치 |
| 연예인·드라마·영화·방송·음악 | 연예·방송 | 스타·연예인(드라마·영화·방송·음악이 더 맞으면 그 주제) |
| 축구·야구·올림픽 등 | 스포츠 | 스포츠 |
| 건강·음식·생활 정보·여행 | 생활·건강 | 건강·의학(음식은 요리·레시피, 여행은 국내여행·세계여행) |

**제목 짓기(호기심):** 후보 5개를 쓰고 아래 6개 중 4개 이상 맞는 것만 고른다.
- **핫이슈의 중심 인물·사건 이름을 제목 맨 앞에 둔다**(사용자 지시 2026-11-10 "오늘꺼 제목이 별로다 잭슨황 이슈를 강조 했어야지").
  경제 각도로 쓴 후속 글도 마찬가지다. 사람들은 뉴스에서 본 그 이름으로 검색하고 클릭한다. 썸네일 큰 글씨에도 그 이름을 넣는다.
  예: '엔비디아 주가 하락 원인, 장중 8.79% 급락…삼성·SK하이닉스는?' ✗ → '젠슨 황 불륜 스캔들에 엔비디아 장중 8.79% 급락…삼성·SK하이닉스는?' ○
1. 사람들이 실제로 치는 검색어를 맨 앞에(자동완성 그대로).
2. 구체적인 숫자나 고유명사(“하루 전”, “14명”, “91%”).
3. 반전·대비(“~인데”, “~했는데”, “A는 웃고 B는 울었다”).
4. 본문이 답하는 열린 질문이나 빈칸(“왜?”, “무엇이 달랐나”, “확인된 것과 아닌 것”).
5. 독자와의 연결(내 돈·내 폰·우리 동네·나도 해당?).
6. 28~40자.
- 형식 예(2026-11-13 메르 블로그 참고): 중심 인물·사건을 앞에 둔 질문 + 끝에 '(feat 노린 검색어)'. 호기심과 검색어를 같이 잡는다.
  예: '젠슨 황 없는 엔비디아, 버틸 수 있을까? (feat 임시 CEO 크레스)'. feat 안에도 본문이 답하는 말만 넣는다.
금지: 본문이 답하지 않는 질문, 의혹을 사실처럼 쓰기, '충격·경악·소름' 같은 빈 자극어, 따옴표 안에 하지 않은 말, 피해자·사생활 자극.

**썸네일(대표 이미지):** `node blog/naverpack/thumb.js <thumb.json> <images>` 로 정사각형 00.png 를 만들어 **글의 첫 이미지**로 넣는다
(블록에 `"thumb": true`). 제목을 그대로 옮기지 말고 한 장면으로 줄인다.
- 큰 글씨 2~3줄, 줄당 7자 안팎(길면 글씨가 작아져 검색 결과에서 안 읽힌다). 핵심 낱말·숫자 하나에 형광펜(`hl`).
- 오른쪽 위 배지는 '왜?' '?' 또는 핵심 숫자. 위쪽 작은 띠(`kicker`)는 분야나 맥락('어제 가장 많이 본 뉴스', '로또 1249회').
- 아래 한 줄(`sub`)은 글을 읽으면 무엇을 알게 되는지('확인된 것과 아닌 것', '3가지로 정리').
- 테마: 사건·경고 red, 정치·사회 navy, 돈·경제 green, 연예·문화 purple, 그 밖 black. 인물 사진·로고·보도 사진은 쓰지 않는다.
- 그린 뒤 이미지를 열어 줄바꿈·잘림을 확인한다(출력에 overflow true 면 줄을 줄인다).
- 도입 첫 문장도 같은 호기심으로 쓰고, 1번 문단에서 바로 답한다.


- **전날 가장 이슈였던 경제·시장 뉴스 하나**를 다룬다.
  '전날'은 한국 시간 어제 하루와 간밤 미국·유럽 시장 마감까지다(실행 시점 기준 지난 24시간).
  국내(증시·환율·금리·부동산·정책)와 해외(연준·유가·빅테크·지정학) 모두 후보.
- **기준은 '사람들이 가장 궁금해할 만한 것'이다**(사용자 지시 2026-11-04). 먼저
  `python3 -I blog/hot_topics.py` 를 돌려 실제 공개 순위를 본다.
  - 네이버 뉴스 '많이 본 뉴스'(경제지 상위 5개, 일반 언론사 상위 5개 중 경제 기사)
  - 네이버 뉴스 '댓글 많은 뉴스' 중 경제 기사
  - 구글 트렌드 한국 급상승 검색어(대략 검색량)
  여러 언론사 순위에 같은 이슈가 겹쳐 오를수록 우선한다. 연예·사건 기사는 경제 낱말이 들어 있어도 빼고,
  "내 돈·내 집·내 연금에 무슨 일?"로 이어지는 이슈를 고른다.
- 순위 근거와 함께 시장 근거도 본다: 증시·환율·금리·유가가 크게 움직였는지, 정부·중앙은행의 공식 발표인지.
  둘이 겹치는 이슈가 가장 좋다. 순위·검색량은 스크립트 출력에 있는 것만 쓰고, 실제 자료 없이 지어내지 않는다.
- 보고에는 고른 근거를 한 줄로 적는다(예: "경제지 많이 본 뉴스 4곳 상위·댓글 많은 뉴스 2곳 + 코스피 장중 400포인트 등락").
- **지난 7일 안에 다룬 주제는 피한다.** `blog/` 의 파일 이름과 제목을 먼저 확인한다.
  전날 가장 큰 이슈가 이미 다룬 주제라도 큰 진전(예: FOMC 결과 발표)이면 "후속편"으로 다루고,
  진전이 없으면 전날 두 번째로 큰 이슈를 고른다.
- "원리부터 쌓아 올려 전날 뉴스로 연결"할 수 있게 쓴다
  (단순 시세 나열·속보 요약은 피한다).
- 다루지 않는 것: 개별 종목 매수·매도 추천, 확인 안 된 루머가 핵심인 이슈,
  Anthropic(작성 도구 제공사) 관련 이슈(이해충돌).

## 2. 조사

- 서로 다른 출처 **3곳 이상**에서 사실을 확인한다. 기사 원문을 열어 숫자를 직접 확인한다.
- 숫자마다 날짜를 붙인다(언제 기준인지). 출처끼리 수치가 다르면 범위로 쓰거나 "보도마다 차이" 표시.
- 확인 안 된 내용은 "~라는 보도가 나옴"처럼 보도임을 밝힌다. 인용문을 지어내지 않는다.
- 다른 블로그(메르 블로그 포함)의 문장을 옮기지 않는다. 형식만 따르고 문장은 새로 쓴다.

## 3. 형식

- **제목**: 클릭하고 싶게, 그러나 본문이 증명하는 만큼만 세게. 30~45자.
  - **검색어 맞추기**(사용자 목표 2026-11-07 "돈을 빨리 많이": 수익은 검색 유입에서 나온다):
    `python3 -I blog/keywords.py <핵심 낱말>` 로 네이버 자동완성 검색어를 보고, 주제에 맞는 검색어를
    제목 앞쪽과 태그에 띄어쓰기까지 그대로 넣는다(예: '레버리지 ETF', '반대매매 유예'). 뉴스 낱말보다 사람들이 치는 말을 쓴다.
  - 쓰는 장치(2개 이상 섞는다):
    - 눈에 박히는 구체 숫자를 앞에: "반대표 2장", "117달러", "하루 3%"
    - 반전·대비: "동결했는데 왜 긴축?", "수출은 사상 최대인데 왜 불안?"
    - 독자 지갑과 연결: "내 예금 이자", "연금 계좌", "대출 금리"
    - 궁금증을 남기는 질문형 끝맺음: "~하는 진짜 이유", "~가 의미하는 것"
  - 예) 밋밋함 "연준이 금리를 동결했는데, 왜 '긴축은 안 끝났다'는 말이 나올까?"
    → 어그로 "금리 동결인데 반대표 2장… 연준이 '12월 인상' 문을 열어둔 이유"
  - 금지: 본문이 뒷받침 못 하는 과장(폭락·대참사·역대급을 사실 없이), 가짜 긴급성
    ("지금 당장 팔아라"), 종목 매수·매도 지시, 제목의 질문에 본문이 답하지 않는 낚시,
    따옴표 안에 실제로 하지 않은 말 넣기. '숨긴'·'진짜 이유' 같은 표현은 본문에서
    그 근거(발언·수치)를 분명히 보여줄 때만 쓴다.
- **도입**: 한 줄. 예) "어제 ○○ 소식이 하루 종일 시장을 흔들어서 정리해 봅니다."
- **본문**: 번호를 붙인 짧은 문장 60~80개. 끝맺음은 "~임 / ~함 / ~됨 / ~있음".
  - 한 문장에 사실 하나.
  - 기초 개념(용어 뜻, 구조) → 배경(지난 흐름) → 전날 사건 → 파급 경로 → 한국 영향 순서.
  - 일상 비유 2~3개(쌀, 깔때기, 택배처럼 누구나 아는 것).
  - "지금까지 흐름을 따라왔으면 ○일 보도를 이해할 수 있을 것임" 같은 연결 문장을 한 번 넣는다.
  - 끝부분에 노후·연금·가계 자산 관점 2~3문장(은퇴노트 독자용). 투자 권유는 하지 않는다.
- **마무리**: `한줄 코멘트.` 로 시작하는 3~4문장 요약 + 앞으로 볼 일정(지표 발표·회의 날짜).
- **면책**: `※ 정보 제공 목적의 글이며 투자 권유가 아닙니다.`
- **분량**: 본문 3,500~4,500자(공백 포함).
- 사진 자리(`[사진: …]`)는 넣지 않는다.
- **이미지(2026-11-13 사용자 "글에 이미지는 없어?"):** 은퇴노트 글마다 2개 — 도입 문단 바로 뒤에 썸네일, 본문 가운데에 도표.
  `node blog/naverpack/thumb.js <thumb.json> blog/blogger_img/<날짜>_<이름>` (thumb.json 에 `"brand": "은퇴노트"`, 네이버 썸네일과 문구·테마는 따로)
  와 `chart.js`·`timeline.js` 로 같은 폴더에 만든다. 본문에는 한 줄로 `![캡션](blog/blogger_img/<날짜>_<이름>/00.png)` 를 쓴다.
  `publish-blogger.mjs` 가 공개 저장소의 raw 주소(그 이미지를 커밋한 해시)로 바꾼다. 이미지는 .md 와 같은 커밋이나 그 전에 커밋한다
  (커밋되지 않은 이미지가 있으면 게시하지 않고 멈춘다). 도표 숫자는 본문에도 있어야 하고, 이미지를 열어 글자 겹침·잘림을 확인한다.

## 4. 파일

- 경로: `blog/YYYY-MM-DD_<영문-짧은-이름>.md` (예: `2026-10-28_fomc-hold.md`)
- 1행: `# 제목`
- 2행: `<!-- labels: 키워드1, 키워드2, 키워드3 -->` (블로거 라벨, 3~5개)
- 본문 → 한줄 코멘트 → 면책 → `---` → `출처` → 출처 목록
- 출처 목록은 링크 형식: `- [매체, 「기사 제목」(날짜)](https://주소)`

## 5. 게시

```
node blog/publish-blogger.mjs blog/<파일>.md
```

- 필요한 환경변수: `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` `GOOGLE_REFRESH_TOKEN` `BLOGGER_BLOG_ID`
- 없으면 게시를 건너뛰고 "키 미설정"으로 보고한다(글 파일은 저장·커밋).
- 이미 게시한 파일은 `blog/published.json` 에 남아 다시 올라가지 않는다.
- **자동 게시(2026-11-13 사용자 지시 "앞으로는 자동으로 올릴수 있게 구글 블로거에 올리자"):** `.github/workflows/blogger-publish.yml` 이
  `claude/blog-daily` 에 새 글(`blog/20*.md`)이 푸시되면 GitHub Actions 에서 게시하고 `published.json` 을 커밋한다. 키 4개는 저장소
  Settings → Secrets and variables → Actions 에만 둔다(채팅·파일 금지). 키 등록 전에 밀린 글·실패한 글은 `blog/blogger_queue.txt` 에 적어 푸시하면 다시 시도한다.
  확인: 푸시 2~3분 뒤 `git pull` 해 `published.json` 에 그 파일이 있으면 URL 을 curl 로 열어 HTTP 200·제목을 본 뒤에만 '게시 완료'라고 한다.
  없으면 Actions 실행 결과(키 미설정 경고인지 오류인지)를 보고한다. 이 세션에서 직접 `publish-blogger.mjs`(--dry 아닌)를 돌리지 않는다.
  Actions 가 `published.json` 을 커밋하므로, 세션의 푸시가 거절되면 `git pull --rebase origin claude/blog-daily` 뒤 다시 푸시한다.
