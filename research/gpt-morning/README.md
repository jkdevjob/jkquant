# 매일 08:00 지피티 전체 연구 보고

모델 연구 자동화는 매일 07:00 KST에 검토를 시작하고 검증된 보고 자료만 이 저장소의 `research/gpt-morning` 브랜치에 기록한다. 운영 코드·전략·주문·매매 장부는 이 자동화가 변경하지 않는다. 기존 클로드 07:07 연구/08:00 보고는 별도 경로로 유지한다.

## 데이터 경로

- 날짜 기록: `research/gpt-morning/YYYY-MM-DD.json` (한 번 작성한 원본을 덮어쓰지 않는다)
- 현재 입력: `research/gpt-morning/latest.json`
- 브랜치 초기값은 최신 main이다. 데이터를 커밋하면 `.github/workflows/gpt-morning-report.yml`이 검증해 서버에 예약한다. 보고서를 예약하는 워크플로는 예약 cron을 사용하지 않는다.
- 실제 발송은 기존 푸시 Worker의 Durable Object alarm이 한국 08:00에 수행한다. 기존 :07/:37 cron은 알람이 없을 때 다음 08:00을 복구한다. 준비 자료가 없으면 미완료를 명시한 보고를 보낸다. 늦게 제출한 보고를 08:00에 보낸 것처럼 표시하지 않는다.
- 보고 링크는 소유자 인증을 유지한 `/scalping?strategy=daily&morningReport=YYYY-MM-DD`이다. 푸시는 기존 `gpt` 전체 탭 동의 기기만, 텔레그램은 기존 프로젝트 수신방만 사용한다. 성공한 기기·메시지는 재전송하지 않는다. 텔레그램 전송 결과가 불명확하면 재시도하지 않는다.
- 설정 화면과 같이 다섯 개별 탭을 모두 켠 기존 기기도 전체 보고 동의로 인식한다. 일부 탭·다른 연구만 켠 기기는 제외한다. 발송 대상 0건이었던 날짜는 같은 보고서를 재제출하면 새로 인식한 전체 동의 기기에 한 번 보완 전송하며, 이미 보낸 텔레그램과 원본 보고서는 유지한다.

## JSON 계약(schema 1)

`date`는 보고일 KST, `preparedAt`은 실제 작성 완료 ISO 시각, `mainSha`는 확인한 main 40자리 SHA, `summary`는 260자 이하이다. 개인정보·계좌 식별자·API 키·실계좌 주문/잔액은 기록하지 않는다.

`sections`에 아래 일곱 `tab`을 각각 한 번 넣는다. 각 항목은 `status`, `findings`, `nextTest`, `evidence`를 가진다.

| tab | 검토 |
|---|---|
| today | 전체 상태·데이터 시각·전일 확정/미확정 구분 |
| opening | 시초가 운영 원본·비용·메인과 그림자 검증 |
| daytrading | 슬롯 계좌손익·체결 품질·재현성 |
| crypto | 코인 시간대·추세/변동성·완료 봉/비용 |
| soxl | 미국 거래일·DST·당일청산·변동성/비용 |
| tenbagger | 고정 가설·등록 후 관찰·실패 대조·미성숙 표본 |
| duel | 지피티와 클로드를 같은 날짜/자금/비용 조건으로 대조 |

상태는 `verified`(근거 URL 필수), `collecting`, `blocked`, `no_change` 중 하나다. `findings`는 700자, `nextTest`는 350자까지이며 근거는 HTTPS URL 최대 4개다. 검증을 실행하지 못한 결과를 검증 성공/새 수익으로 부르지 않는다. 기존 기록과 비교해 한 가지 새 가설을 집중 검증하고, 채택·보류·탈락과 다음 시험을 남긴다. 원본 앱 실행환경과 실제 원천을 사용하며 가짜 시세·별도 간이 엔진을 공식 성과로 제시하지 않는다.
